# SMC/ICT 1호기 — research_ML2 세션 인계

작성 기준: 2026-08-18

## 현재 결론

현재 후보는 장기 continuous 평가나 실시간 paper로 넘길 상태가 아니다. 다만 기존 접근의 병목과 다음 돌파구는 선명해졌다.

쉽알남식 매매를 `OB 전략`, `FVG 전략`, `채널 전략`처럼 독립 도구 전략으로 쪼개지 않는다. 실행 논리는 다음 하나의 인과 흐름이어야 한다.

```text
가격·거래량 관찰
→ 방향성과 유동성 상태 판단
→ 추세선·채널·수평 구조로 중요한 위치와 시장 구조 해석
→ sweep/reclaim, acceptance, fakeout/trap, rotation 같은 유동성 사건 판별
→ 사건 이후 첫 방어·첫 되돌림에서 OB/FVG/retest로 진입 가격 정밀화
→ 사건이 틀렸음을 뜻하는 구조적 지점에 손절
→ 아직 소비되지 않은 반대 유동성·구조에 목표
→ BTC/ETH/SOL/XRP 중 한 기회만 단일계좌·단일 글로벌 포지션으로 실행
```

기존 RE1 완결 계획에 마지막 ML 분류기만 붙이는 방식은 충분하지 않았다. 방향·진입·손절·목표 geometry가 약하면 meta-labeling은 구제하지 못한다. 현재 연구 방향은 `episode-conditioned integrated auction policy`다. ML은 임의 주문을 발명하지 않고, 완결된 사건별 계획 후보 사이에서 시장 상태·방향·계획 품질·abstention을 판단하는 상위 router 역할을 맡는다.

## 자료에서 압축한 시장 논리

- 방향성 판단의 중심은 유동성이다. 가격이 어디의 주문을 가져갔는지, 경계 밖을 수용했는지 다시 안으로 회귀했는지가 먼저다.
- 추세선·채널·수평 구조는 방향, 속도, 범위, 중요한 경계와 구조 전환을 해석한다.
- Fakeout/Trap, sweep/reclaim, acceptance는 구조 위에서 발생한 유동성 사건이다.
- OB/FVG는 사건 이후 남은 footprint와 좋은 가격의 되돌림 위치를 정밀화한다.
- 거래량·taker flow는 돌파가 initiative인지 exhaustion인지, 반대 체결이 흡수되는지, 첫 되돌림이 실제로 방어되는지를 판단한다.
- 손절은 임의 ATR 폭이 아니라 사건의 인과 가설이 무효가 되는 지점이다.
- 목표는 진입 전에 존재하며 아직 소비되지 않은 반대 유동성·구조다.

여러 근거를 단순 합산하지 않는다. 위치, 사건, 방향, 반응, 진입, 무효화, 목표가 서로 다른 질문을 해결하며 하나의 거래 가설을 완성해야 한다.

## 먼저 해결한 구현 문제

1. 15/5/1분 mature-diagonal 엔진에 부모 60분 봉을 넘기던 계약 오류.
2. 잘못된 zone-strength 필드명 때문에 핵심 강도가 0이 되던 오류.
3. process-global `rule_provenance`를 개별 계획 메커니즘처럼 읽던 오류.
4. target 조회 실패를 fresh target으로 오인할 수 있던 오류.
5. 최종 router 이전 broad common-factor veto가 반대-context 표본을 없애던 selected-sample bias.
6. 단순 expected-R 선택을 고정 3% 위험의 expected log-growth로 교체.
7. 독립 chunk의 plan/causal-event ID 충돌을 source-checksum namespace로 교정.

이는 코드·계약을 정상화한 것이며 알파 증거가 아니다.

## 기존 고정 계획 + meta-labeling의 한계

여러 counterfactual artifact의 완결 계획 약 210건 중 target-first는 59건, stop-first는 151건으로 기본 성공률은 약 28.1%였다. leave-one-period-out 분류 AUC는 대략 0.61~0.63 수준이었지만 높은 확률 후보를 선택해도 보수적 비용 후 평균 R은 음수였다.

상태 구분 가능성은 조금 있었지만, 좁은 손절·늦은 진입·먼 목표·약한 causal geometry가 기본 경제성을 훼손했다. 분류기만 개선하기보다 계획 생성 계층을 시장 사건 중심으로 재설계해야 한다.

실행·위험 계층은 정상에 가까웠다. 전 구간 risk-budget breach 0, emergency protective exit 0, max risk utilization 약 1.0이었다. 실패는 주로 시장논리다.

- sweep/reclaim만으로 방향을 확정한 것이 거칠다.
- 첫 defended return이 실제 control transfer인지 일시 반등인지 구분이 약하다.
- 15분 footprint와 5분 trigger 사이 acceptance/rotation 상태가 충분하지 않다.
- target이 구조적이어도 실제 경로상 너무 멀거나 약해진 목적지일 수 있다.
- stop이 구조적으로 맞아도 entry가 늦으면 경제성이 나쁘다.
- continuation과 reversal을 hard rule로 이분하지 말고 상위 liquidity/state router가 필요하다.

threshold 조정으로 이 후보를 계속 살리지 않는다. 유동성 사건 ownership, 첫-return lifecycle, 사전 고정 계획, Nautilus 실행·위험 계층만 보존하고 방향·상태·반응·entry/target geometry를 재구성한다.

다음 세션의 첫 구현 작업:

1. `causal_continuation_policy_v2.py`와 `run_mtf_backtest_ml2_causal_continuation_v2.py`를 정상 source로 복구한다.
2. 가능하면 base64 bootstrap 대신 정상 source를 직접 커밋한다.
3. bootstrap이 불가피하면 tar 생성 후 `gzip -t`, `tar -tzf`, sha256, base64 encode/decode, `cmp`, 재차 `gzip -t`까지 통과시킨다.
4. PR #17 head를 최신 base에 맞추거나 새 execution carrier PR로 다섯 구간을 다시 실행한다.
5. 실제 결과를 보기 전 continuation-v2를 평가하지 않는다.

## 다음 채팅의 작업 순서

1. continuation-v2 source 운송 경로를 복구하고 다섯 분리 구간 실행을 완료한다.
2. `trade_audit.csv`, `decision_events.csv`, `scenario_events.jsonl`, `mtf_trade_windows.jsonl`에서 방향, liquidity event, control transfer, entry, invalidation, target 중 반복 실패 책임층을 찾는다.
3. fresh router에서 유용해 보인 path efficiency, break-event density, common-factor 종료 방향, local residual, absorption, prior-event state를 decision-time causal feature로만 이식한다.
4. 다음 통합 구조로 재구성한다.

```text
market state / liquidity map
→ episode detector
   ├─ sweep-reclaim reversal/rotation
   ├─ accepted-break continuation
   ├─ failed-acceptance trap
   └─ 필요하면 다른 독립 causal mechanism
→ 각 episode의 소수 immutable plan lattice
→ calibrated state router: 방향·계획 선택 또는 abstain
→ global single-slot arbitration
→ Nautilus execution / fixed 3% risk / full entry-full exit
```

개별 family 결과를 합쳐 최종 성과라고 하지 않는다. 충분히 가망이 확인되고 구조가 고정된 뒤에만 더 뒤의 untouched 기간에서 네 종목을 하나의 continuous account로 실행한다.
